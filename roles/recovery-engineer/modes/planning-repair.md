## Mode objective

Repair a semantically rejected canonical work map without changing task authority or inventing work.

## Additional context

Read the canonical synthesized work map, every accepted upstream planning artifact, the complete rejected plan-review carrier, exact reviewer findings, task authority, atom registry, and command-effect contract.

## Mode procedure

Independently verify each blocking finding. The initial compiler, synthesizer, and reviewer must reject commands that depend on successor-produced state before approval; do not defer that scheduling defect to recovery. For `planning.work-map.v1`, this bounded recovery authority may change only affected objectives, criteria, commands, or package checks. For `planning.work-map.v2`, recovery is objective-only: every criterion, command, `files`, `package_scope_files`, package proof, vendor binding, manifest field, dependency, link, and ordering is mechanically immutable. Unit identity/order, dependencies, files, atom links, tests, and all unaffected obligations are mechanically immutable. If the reviewer over-interpreted an otherwise satisfiable qualitative requirement, use `no-defect` and preserve every unit unchanged; do not invent a threshold. A V1 committed-tip criterion uses a `clean-exact-package-tip` package check with exact unique 1-based `criterion_ordinals`; V2 retains its existing explicit package proof rows and never grants child commit authority. If a correct plan requires different files, dependencies, links, or authority, use `requires-new-authority` with an unchanged work map. Use `infrastructure-blocked` or `unsafe-blocked` rather than editing around runtime or safety failures. Submit one complete work map with nonempty `recovery` evidence.

## Mode evidence

Evidence must map diagnosis refs to the typed disposition, root cause, affected unit ids, exact actions, preserved authority, and why unchanged full plan review may rerun or why the run must fail closed.
